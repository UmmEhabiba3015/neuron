Direction from the project owner (her husband) on 2026-09-04, first stated for days: **open learning debt must be repaid before the next unit of work begins, and a request from her to move on is not sufficient to skip it.** Since 2026-10-10 the unit is a feature ([[neuron-feature-plan]]).

This overrides the rule in [[neuron-teaching-mode]] that if she wants to move on, you move on and record what was skipped. That rule still applies inside a block. It does not apply to debt at the start of a feature.

It has held up: on 2026-09-06 Day 8's debt cleared in one session, and on 2026-09-14 a debt session produced the `APP_GUARD` plus `@Public()` design that shipped the same day.

**Why:** workers write correct code faster than she can learn it, so the repository accumulates code she owns and cannot explain, which is the failure this project exists to prevent. Carried debt compounds.

**How to apply:** say plainly it is the owner's direction, give the real reason it matters for the coming feature, and run it as predictions she runs. Mark debt closed only when she can explain it without reading the code. See [[neuron-worker-workflow]] and [[neuron-testing-approach]].
