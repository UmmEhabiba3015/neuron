Journal / implementation reference

A design system for quiet, honest reflection.

The visual language behind Journal, translated into reusable foundations, accessible controls, composed patterns and application-ready HTML/JavaScript. This guide documents the approved system; ../lock.css revision 49 remains the source of truth.

Principles

The system protects the hierarchy between a person's record and the product around it. Warmth comes from paper, type and structure, not decorative wellness conventions.

The user writes in ink

User-authored words use --ink. Product-authored language uses rust, a smaller size and a labelled position.

Audio owns forest

--block marks audio and the current destination only. It is never a generic accent colour.

Paper does not float

Hierarchy comes from flat fills, hairlines and spacing. Product surfaces have no shadow and almost no rounding.

Silence is valid

No streak pressure, red errors, disabled controls or empty illustrations. If an action is unavailable, explain why in a sentence.

Meaning survives greyscale

Colour is reinforced by words, position, outlines, waveform shape and hierarchy.

The record stays still

Only four product-authored actions move. A person's words never animate.

Runtime

The prototype classes remain the visual API. This behavior layer turns their semantic markup into application components while leaving persistence, routing and server data in the application that consumes them.

Install once, mount per route

import { mountJournalComponents } from "./components/journal-components.js";

const journal = mountJournalComponents(routeElement, {
  composer: {
    onSave: ({ value, excluded }) => api.entries.create({ value, excluded }),
    onRecord: () => router.push("/talk")
  },
  mood: { onChange: (mood) => api.days.setMood(mood) }
});

// Keep this in the framework's route/component cleanup.
onRouteLeave(() => journal.destroy());

Named exports can be mounted from React effects, Vue lifecycle hooks, Svelte actions or plain JavaScript. TypeScript declarations ship beside the module.

Date writes

Handwritten values only. Printed prices and labels remain still.

--g-date · 500ms
Product line types

Only text wrapped in .gline. Never the user's question.

--g-type · 820ms / 48 steps
Waveform draws

Starts at 110ms. Desktop duration is a descendant override at a 1200px app width.

--g-wave · 360ms / 520ms desktop
Composer rises

Only when an out-of-memory option exists. The travel reveals that option.

--g-comp · 240ms over 64px

The note disclosure also uses the established 420ms open/close behaviour, but it is an interaction state of .said, not a fifth load animation. Reduced-motion removes motion entirely. Error and recovery text stays still.

Composer: four occasions, no extra entrance

Open the app: rise. Scroll further into the journal: tuck. Scroll back: reveal. Interact while tucked: rise. Interact while already open: stay still. The scroll timeline scrubs linearly from 24 to 120px; it has no timed easing. Focus transitions the registered --g-tuckable value over 240ms. Keep the scroll animation running.

The integrated scroll rule uses forwards fill for the tuck. It stays tucked after 120px and does not apply before 24px, preserving the opening rise. Typing and saved-state fixtures suppress all load effects while retaining scroll interaction.

Note: one clock in both directions

Keep native details and the .lblbox wrapper inside its summary. The labels roll together while the fully opaque content lifts 20px, all over 420ms. Reverse on close. Height growth uses interpolate-size where supported; otherwise height steps open and the content remains available. Do not replace it with a fixed height.

Product motion preference and capability fallbacks

In production without the review override, reduced motion removes every animation and transition, including scroll tuck and note travel. No fade, no shortened duration, no preference override. Press feedback is an instant state. Without scroll timelines the composer stays open. Without interpolated height the note steps open. The original review measured those fallbacks in Gecko; capability checks remain the authority.

Delivered files follow the device's reduced-motion setting. The designer's review copies add data-motion-review="play" on their root element so the full design and Replay run with Windows animations disabled; the handover package removes it. Never ship it in the product.

What a build must preserve

Back restores a drawn screen. Typing and Save update Today in place. None may replay any of the four load effects. Static walkthroughs cannot enforce that lifecycle: .restate suppresses only their composer entrance. Keep accessible input labels, keyboard focus and drafts; never delay an action for animation. The runtime adapter does not own route arrival policy.

Later account and flow pages

The completed v2 _motion files are the implementation reference for all three platforms. New handover pages reuse their product-line gesture on the first introductory sentence: g-draw with stepped progress, one step per character, at 820ms / 48 per character. The span's --aj-c-text-chars determines its duration. Existing copy, line wrapping, fields and navigation are retained.

Errors, recovery warnings, permission failures, form fields and notices remain immediately readable. Pages without introductory copy use the same 160ms press and 280ms release feedback. The printed account masthead stays still. There is no new page entrance or loading loop.

Review the full integrated handover: mobile, tablet, desktop. Each reflects the current v3 states. The Today specimen above illustrates the primitives; it is not the full implementation.

Never animate the user's record, transcripts, restated questions, masthead, error state or progress. No ambient loops or breathing microphone. Privacy settings and the account mastheads remain still. Preserve the overview's link mark (dotted underline and chevron): it identifies the product's own words.
